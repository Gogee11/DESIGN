# 消融实验

## 实验目的

本节旨在回答两个问题：第一，LLM-AGR 默认配置下隐私泄漏上升究竟来自哪一个关键模块；第二，在保持推荐性能基本稳定的前提下，哪些超参数会显著影响成员推断攻击（Membership Inference Attack, MIA）的成功率。围绕这一目标，本文重点考察信息瓶颈系数 `β` 与结构对比损失权重 `str_weight` 对推荐效用和隐私风险的影响，并进一步补充验证 LLM kNN 增强图规模 `aug_top_k` 是否构成额外泄漏来源。

## 实验设置

消融实验基于 `digital_music` 数据集进行，推荐骨干模型为 `lightgcn_agr`，随机种子固定为 2025，攻击器采用逻辑回归（LR）成员推断攻击。主消融采用 `3×3` 网格搜索：令 `β ∈ {0, 1, 4}`，`str_weight ∈ {0, 0.05, 0.2}`，其余训练配置保持一致。实验同时报告推荐指标 Recall@20 和隐私指标 MIA AUC，其中 Recall@20 越高表示推荐性能越好，AUC 越低表示模型越不容易被攻击者识别成员身份。为进一步隔离 LLM 增强图的影响，本文在 `(β=0, str_weight=0)` 的基础上额外设置 `aug_top_k ∈ {0, 3, 10, 20}` 的补充消融。

## 实验结果

作为参考，LightGCN 基线的 Recall@20 为 0.2414，MIA AUC 为 0.9016；AGR 默认配置（`β=1, str_weight=0.05`）的 Recall@20 为 0.2520，MIA AUC 为 0.9341。

| β | str_weight | Recall@20 | MIA AUC |
|---|---:|---:|---:|
| 0 | 0    | 0.2419 | 0.8857 |
| 0 | 0.05 | 0.2505 | 0.9293 |
| 0 | 0.2  | 0.2212 | 0.9534 |
| 1 | 0    | 0.2548 | 0.9097 |
| 1 | 0.05 | 0.2499 | 0.9303 |
| 1 | 0.2  | 0.2203 | 0.9493 |
| 4 | 0    | 0.2483 | 0.9036 |
| 4 | 0.05 | 0.2499 | 0.9348 |
| 4 | 0.2  | 0.2208 | 0.9521 |

从表中可以看出，`str_weight` 是影响隐私泄漏的主导因素。在固定 `β` 的情况下，当 `str_weight` 从 0 增加到 0.05 和 0.2 时，AUC 均呈单调上升趋势：例如在 `β=0` 时，AUC 从 0.8857 上升到 0.9293 和 0.9534，累计增加 0.0677；在 `β=4` 时，AUC 也从 0.9036 上升到 0.9348 和 0.9521。相比之下，在固定 `str_weight` 的前提下调节 `β`，AUC 的波动明显更小：当 `str_weight=0.05` 时，三组 AUC 仅在 0.9293 到 0.9348 之间变化；当 `str_weight=0.2` 时，三组 AUC 也仅在 0.9493 到 0.9534 之间波动。这说明隐私风险的主要来源并不是信息瓶颈项本身，而是结构对比损失持续强化了可被攻击器利用的成员特征。

从推荐性能看，`str_weight` 的增大并未带来稳定收益，反而在高权重下明显损害效果。当 `str_weight=0.2` 时，三组 Recall@20 均下降到约 0.220，明显低于 `str_weight=0` 或 0.05 时的水平。也就是说，较大的结构对比权重同时带来了“更高泄漏”与“更低推荐效果”的双重退化，不构成有效的效用-隐私折中。

在三组低泄漏配置中，`(β=0, str_weight=0)` 和 `(β=1, str_weight=0)` 最具代表性。前者的 Recall@20 为 0.2419，几乎与 LightGCN 基线持平，但 AUC 从 0.9016 降至 0.8857，说明仅去除结构对比项就可以获得严格的 Pareto 改进；后者的 Recall@20 达到全表最高的 0.2548，在获得更强推荐性能的同时，AUC 仅为 0.9097，说明 `β` 可以作为次级调节旋钮，在不显著恶化隐私的情况下提升推荐效果。

补充消融进一步验证了 LLM kNN 增强图规模并非主要泄漏来源。在 phase13 的统一设置下，`aug_top_k` 从 0 增加到 3、10、20 时，Recall@20 仅在 0.2445 到 0.2448 之间波动，AUC 仅在 0.88920 到 0.88922 之间变化，几乎可以视为不变。这说明前文观察到的隐私风险并不来自邻居数量的增加，而是来自结构对比目标对表示空间的约束方式。

## 结果分析与结论

综合上述结果，可以得到以下结论。首先，LLM-AGR 默认配置更易遭受成员推断攻击，其根因不是 LLM 增强图或信息瓶颈模块本身，而是结构对比损失项。其次，将 `str_weight` 设为 0 是最直接且有效的改进方式：它既能显著降低 MIA AUC，又不会破坏推荐性能。最后，`β` 的作用更多体现在推荐性能的细粒度调节，而不是决定隐私风险的主要方向。因此，后续隐私增强方法的设计应以移除或弱化结构对比项为前提，再在此基础上叠加对抗训练、置信度正则或嵌入压缩等机制，以进一步优化隐私-效用权衡。
